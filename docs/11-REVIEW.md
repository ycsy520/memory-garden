## 第二部分：风险评估

### 一、响应式与多端布局

#### 🔴 R1 · 雾化过渡在低端设备上压缩逻辑窗口

- **事实**：回合切换执行 300ms 雾化过渡（`transition` 相位）。  
- **风险**：低端 GPU 若在 300ms 内无法完成「清除 + 遮罩 + 淡入」，rAF 状态机仍在正常累加 `phaseAge`，导致 **思考窗口被无形压缩**，极端情况下直接跳过回合判定。  
- **修复基准**：`transition` 相位内若检测 `dt > 80ms`，补偿 `phaseAge` 或暂停逻辑时钟直至渲染追上。

#### 🔴 R2 · 空间模式网格在 <360px 屏幕上与按钮重叠

- **事实**：空间模式需要 3×3 花坛网格，最小格尺寸建议 ≥64px。  
- **风险**：宽度 320px 设备上，64px×3 = 192px 网格 + 双侧 padding，剩余垂直空间极可能压迫底部操作区，导致格子与按钮**触控盒重叠**，误触率高。  
- **验证缺口**：缺少 320×568 视口下的触控热区测试用例。

#### 🟡 R3 · `prefers-reduced-motion` 导致状态机空转延迟

- **事实**：CSS 动画设为 0ms，但 JS 状态机 `fading`（300ms）+ `transition`（400ms）时长硬编码。  
- **风险**：用户感知画面瞬间切换后，仍需等待约 700ms 才进入下一回合，主观体验为**无响应卡顿**。  
- **修复基准**：初始化时读取 `window.matchMedia('(prefers-reduced-motion: reduce)')`，若为 true 则将 `fadingDuration` 和 `transitionDuration` 动态清零。

### 二、评分系统与科学内核

#### 🔴 R4 · Timeout 权重对老年用户的系统性惩罚

- **事实**：限时双按钮，超时记为 `timeout`；N 值自适应根据综合分数升降。  
- **风险**：若 `timeout` 扣分权重等同 `False Alarm`，老年人因生理反应延迟导致得分持续低迷，触发**频繁强制降 N**，甚至退回"练习散步"，直接打击使用意愿。  
- **修复基准**：
  1. `timeout` 扣分权重应远低于 `falseAlarm`（建议 ≤30%）；
  2. 若某局 `timeoutRate > 40%`，设 `validForAdaptation: false`，仅给予节奏提示，**不触发自适应降 N**。

#### 🔴 R5 · Lure 干扰项错误混入基础误判指标

- **事实**：训练中引入 `nMinus1`（前一个）与 `similarStimulus`（形近）两类 Lure。  
- **风险**：Lure 回合的错误反映**冲动抑制失败**，而非工作记忆维持失败。若 Lure False Alarm 与普通 False Alarm 混同计算，自适应系统将错误评估用户的记忆容量上限，导致**降 N 决策失真**。  
- **修复基准**：`TrialResult` 中独立字段 `lure_false_alarm: boolean`，自适应引擎读取 `falseAlarmRate` 时**排除** Lure 回合。

#### 🟡 R6 · 首局冷启动评分失真

- **事实**：用户首次进入游戏，无历史基线数据。  
- **风险**：首局用户处于学习状态，若结果直接参与自适应计算，可能导致**错误的初始 N 值锚定**（过低则长期停留低难度，过高则立即挫败）。  
- **修复基准**：前 3 局标记 `isWarmup: true`，仅展示鼓励反馈，不写入自适应计算池。

### 三、游戏引擎与异常处理

#### 🔴 R7 · rAF 暂停恢复"死锁"循环

- **事实**：`pause()` 设 `timeScale=0`，`resume()` 设 `timeScale=1`。  
- **风险（精确复现路径）**：  
  1. 用户暂停游戏 → 后台挂起 30 秒；  
  2. 切回点击"继续"→ `resume()` 执行，`timeScale=1`；  
  3. 下一帧 `tick(timestamp)` 计算 `delta = timestamp - lastFrameTime` = **30,000ms**；  
  4. 超过 `>1000ms` 自动暂停阈值 → 状态机**立即再次暂停**；  
  5. 用户再点"继续"→ 无限循环死锁。  
- **修复基准（必须）**：`resume()` 内部强制刷新：`this.lastFrameTime = performance.now()`。

#### 🔴 R8 · 旧模式 Session 数据污染新统计层

- **事实**：旧模式（DualMode / SpatialMode）代码保留但隐藏；老用户 LocalStorage 中存在历史数据。  
- **风险**：旧 Session 缺少 `falseAlarmCount`、`hitRate`、`schemaVersion` 等新字段，新统计页读取时产生 `NaN`/`undefined`，轻则图表异常，重则**页面崩溃**。  
- **修复基准**：所有历史 Session 读取入口，必须过滤：  

  ```js
  sessions.filter(s => s.schemaVersion === 5 && s.mode === 'walk')
  ```

#### 🟡 R9 · PWA 离线升级后叙事 ID 对账失败

- **事实**：`narratives.js` 作为静态数据，版本升级时 ID 或 tier 可能调整；用户离线已解锁的 ID 存储于 LocalStorage。  
- **风险**：新版 `narratives.js` 删除或重命名某个 ID 后，`getNarrativeTier(id)` 返回 `undefined`，导致叙事卡片渲染崩溃。  
- **修复基准**：`getNarrativeTier()` 增加降级路径：ID 不存在时返回 `{ tier: 'legacy', shortText: '（内容已更新）', fullText: '' }`，不抛出异常。

### 四、叙事系统

#### 🟡 R10 · `recentUnlockQueue` 并发写入竞态

- **事实**：`narrativeUnlockEngine` 在每局结束时评估解锁，可能同时产生多个新解锁项推入 `recentUnlockQueue`。  
- **风险**：若引擎在同一 tick 内多次写入队列，且 UI 动画逐条弹出展示，队列消费逻辑若无锁机制，可能出现**重复弹出同一故事**或**遗漏部分故事**的展示错误。  
- **修复基准**：`recentUnlockQueue` 写入时去重（按 ID），消费时确保 `isAnimating` 锁，动画完成后再 `shift()` 取下一条。

#### 🟡 R11 · `shortText` 截断导致日记收藏语义残缺

- **事实**：`FinishedScreen` 展示 `shortText`（摘要），用户可将其收藏至"花园日记"。  
- **风险**：若用户在阅读 `shortText` 前直接点击"收藏"，日记中仅存摘要，打开日记后感到**内容不完整**。交互上未明确区分"先阅读全文"与"直接收藏"。  
- **修复基准**：收藏按钮触发后，同时存入 `fullText`；日记条目展示时默认折叠 `fullText`，提供"展开阅读"入口。

---

### 五、数据持久化

#### 🔴 R12 · LocalStorage 容量上限无保护

- **事实**：每局训练数据、叙事阅读状态、日记条目全部写入 LocalStorage；移动端 Safari 通常限制 5MB。  
- **风险**：长期用户（>180 局）的数据量可能逼近上限，写入失败时若无捕获，**静默数据丢失**——用户解锁的故事和训练记录可能消失且无提示。  
- **修复基准**：所有 `localStorage.setItem()` 调用包裹 `try/catch(QuotaExceededError)`；超限时触发自动清理最旧的 30 局 Session，并通知用户。

## 第四部分：架构正向评价

在指出风险的同时，以下设计决策值得肯定：

- ✅ **时钟解耦**：加工时钟与 N 值分离，是对认知负荷理论的精准应用，避免了"N↑则速度自动加快"的常见设计陷阱。
- ✅ **叙事与状态分离**：`narratives.js` 静态化彻底杜绝了叙事内容被意外 mutate 的问题，Store 只持久化 ID 极大减少了序列化体积。
- ✅ **信号检测论指标**：从 `accuracy` 迁移至 `hitRate + falseAlarmRate` 的决策是认知科学级别的正确升级，为后续科研级数据导出奠定了基础。
- ✅ **rAF 状态机设计**：帧级 `delta` 驱动的相位机相比 `setInterval` 方案在前台稳定性、可暂停性上有本质优势。

---

## 评审结论

> **核心判断：设计方向卓越，边界防御决定上线质量。**

本次重构同时触碰了三个高风险域：**引擎底层计时器**、**数据持久化结构**、**自适应评分模型**。每一个单独重构都需要严格的边界测试，三者同时推进的风险是叠加而非线性的。

**部署前必须清零的红牌项**（按优先级）：

1. **R7** · `resume()` 缺少 `lastFrameTime` 刷新 → 死锁，100% 可复现
2. **R8** · 旧 Session 无 schema 过滤 → 统计页对所有老用户崩溃
3. **R4** · Timeout 惩罚过重 → 老年用户核心体验受损
4. **R12** · LocalStorage 无溢出保护 → 长期用户数据静默丢失
5. **R5** · Lure 错误混入自适应 → N 值评估系统性失真

# RELEASE-READINESS - 上线前收尾与人工测试计划

> 适用版本: v5.2.x
> 更新日期: 2026-07-16
> 目标: 在进入人工测试与封包计划前，用统一标准确认当前版本是否达到可发布候选状态。

---

## 1. 当前目标

当前主线不是继续扩功能，而是完成发布前收尾，确保：

1. 自动化回归重新回到可放行状态
2. 已知高风险项被明确分级为阻断 / 非阻断
3. 人工测试有可执行清单，而不是凭感觉点
4. 人工测试完成后，才能进入封包计划

---

## 2. 当前基线

### 2.1 自动化结果

- `npx playwright test`
  - 结果：`20 passed`
  - 结论：此前因为测试代码未同步产品变化而导致的两条失败已修复
- `npm run test`
  - 结果：上一轮发布准备审计中已通过
  - 结论：单元 / 逻辑层测试当前没有新增阻断信号

### 2.2 当前仍然存在的工程风险

- `npm audit --omit=dev`
  - 结果：`5 vulnerabilities`
  - 分布：`1 low / 1 moderate / 3 high`
  - 重点包：
    - `vite`
    - `rollup`
    - `picomatch`
    - `postcss`
    - `@babel/core`
- 构建输出仍存在 chunk 警告
  - 现象：部分 chunk 大于 `500 kB`
  - 结论：属于性能收尾项，当前先列为非阻断，但封包前应继续观察
- Browserslist 数据过旧
  - 现象：构建与 E2E 时出现 `caniuse-lite is 7 months old`
  - 结论：当前列为非阻断维护项

---

## 3. 阻断项分级

### 3.1 当前阻断项

1. 依赖漏洞尚未处理完成
   - 原因：存在 `vite / rollup / picomatch` 高风险告警
   - 要求：必须先完成“接受风险”或“升级修复”其中一种正式决策，不能跳过
2. 人工测试尚未执行
   - 原因：自动化通过不等于真实发布环境、PWA、横竖屏、切后台、导入导出体验全部无问题
   - 要求：必须完成本文件第 5 节人工清单
3. 封包计划尚未制定
   - 原因：Android / iOS / PWA 的产物链路不同，缺少最终发布路径确认
   - 要求：人工测试通过后再进入封包计划

### 3.2 当前非阻断项

1. Browserslist 数据过旧提示
   - 当前不影响功能正确性
2. chunk size warning
   - 当前不阻止人工测试，但会影响后续性能优化优先级

---

## 4. 发布前执行顺序

### R0 变更冻结

- 除阻断修复外，不再新增功能
- 所有修改必须服务于上线准备

### R1 风险决策

- 对 `npm audit --omit=dev` 的 5 个漏洞做正式结论
- 输出每个风险的处理策略：
  - 立即升级
  - 接受风险并记录原因
  - 延后到封包后版本

### R2 自动化回归

- 重新跑：
  - `npm run test`
  - `npx playwright test`
- 只有两者都无新增失败，才能进入人工测试

### R3 人工测试

- 严格按照第 5 节 checklist 执行
- 每项记录结果：通过 / 失败 / 待复验

### R4 发布阻断项清零

- 只要人工测试中存在 P0 / P1 问题，继续回到修复与回归
- 直到阻断项全部清零

### R5 封包计划

- 明确本次先发平台
- 确认使用：
  - Web/PWA
  - Capacitor Android
  - Capacitor iOS
- 为每个平台分别列出构建、验包、回滚方案

---

## 5. 人工测试清单

以下清单按真实用户路径排序，执行时不要跳点。

### 5.1 首次进入

- 打开应用，确认首屏加载无异常闪屏、黑线、黑框
- 从 Intro 进入 Guide，再进入 Menu
- 首次进入时文案、间距、顶部/底部装饰显示正常
- 手机窄屏下首页底部花园图案完整可见

### 5.2 菜单与开局

- 依次验证四种模式：
  - 散步
  - 花与歌
  - 花坛
  - 花圃
- 每种模式分别验证至少一种节奏：
  - 非限时节奏
  - 限时节奏
- 核对开始文案与标题语义：
  - 晨跑不能再显示“开始散步”
  - 顶部标题必须与模式 / 节奏一致

### 5.3 局内核心链路

- 检查顶部进度条是标准进度条，不是顶部色块堆叠
- 检查暖身三朵花固定在暖身文案上方，不随舞台高度抖动
- 检查“一样 / 不一样”按钮层级、间距、按压反馈
- 检查横屏布局在平板/桌面下的 12 列平衡感
- 检查暂停遮罩样式统一，没有系统原生弹窗残留

### 5.4 失焦与恢复

- 浏览器标签切走后自动暂停
- PWA 切后台后自动暂停
- 返回前台后必须手动点击“恢复游戏”
- 普通模式恢复后计时不从 0 重置
- 非 walk 限时模式恢复后倒计时继续递减，不会卡死

### 5.5 结算与记录

- 完成至少 1 局，进入结算页
- 首局时右侧不应留白
- “过往记录”不再伪装成跨模式“进步趋势”
- 历史记录的模式 / 难度信息展示正确

### 5.6 设置与数据管理

- 导出备份成功
- 打开导出 JSON，确认不包含 `fullTextEntries`
- 导入脱敏备份成功，并恢复本地状态
- 清除数据后回到新用户初始态
- 删除账户后当前会话本地状态同步清空
- 全流程中不出现原生 `alert` / `window.confirm`

### 5.7 登录与同步

- 邮箱登录链路可用
- 已登录状态可触发手动同步
- 登出后本地状态与云同步状态不串号
- 如有测试账号，至少验证一次“登录后拉云”闭环

### 5.8 阅读与辅助页面

- Guide / Mode Guide 正常打开
- Disclaimer / Privacy / Terms / N-back 页面排版正常
- 中英繁切换后关键页面不出现丢 key

### 5.9 PWA 与安装体验

- Chrome 可安装
- 安装后图标、名称、启动页正常
- Service Worker 升级不出现异常旧缓存接管
- PWA 场景下切后台 / 恢复 / 设置 / 导入导出链路正常

## 7. 进入封包计划的前置条件

只有同时满足以下条件，才允许进入封包计划：

1. 自动化回归全部通过
2. 人工测试 checklist 执行完成
3. 发布阻断项已清零
4. 依赖漏洞已完成升级或正式风险接受
5. 目标平台已明确

---

## 8. 当前结论

当前版本已经从“自动化存在阻断”恢复到“自动化可继续放行”，但还**不能直接进入封包**。

当前最合理的下一步顺序是：

1. 先对 `npm audit` 高风险依赖做处理决策
2. 按本文件 checklist 开始人工测试
3. 人工测试完成后，再进入封包计划

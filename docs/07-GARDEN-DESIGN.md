# **07 — 花园主题记忆训练设计文档 GARDEN DESIGN**

> 版本：v5.0  
> 更新：2026-06-29  
> 状态：重构版，可进入 MVP 设计与实现评审  
> 核心方向：以 N-back / Go-No-Go N-back 为科学训练内核，以“记忆花园”为体验语言，面向儿童、成人与老年用户提供分轨体验。  
> 重要声明：本产品是注意力与工作记忆练习工具，不是医疗诊断、治疗或疾病预防工具。

---

## **0. 文档目标**

本文件定义“记忆花园”小游戏的产品体验、科学任务内核、交互规则、反馈机制、节奏系统、无障碍要求、工程架构、数据结构、收集系统与实施路线。

本版本重点解决以下问题：

1. 保留花园叙事，但避免疾病化、幼态化和老年刻板印象。
2. 明确 N-back 任务内核，防止游戏化包装破坏训练有效性。
3. 将儿童、成人、老人从“同一套规则”改为“同一世界观下的分轨体验”。
4. 将默认单按钮玩法定义为 Go-No-Go N-back，并使用适配的评分系统。
5. 修正原方案中节奏参数冲突的问题。
6. 将复杂收集、声音双通道、3D 花园等内容后移，优先保证 MVP 稳定。
7. 增加 trial generator、lure、评分、事件日志、自适应、暂停恢复等核心工程规格。
8. 建立温和但有效的学习反馈，不再采用“完全无反馈”的极端策略。

## **1. 设计原则**

### **1.1 不可违背原则**

1. **科学内核优先**  
   花园主题、动画、奖励和叙事不得破坏 N-back / Go-No-Go N-back 的任务结构。训练内核必须可解释、可复现、可测试。

2. **低压力，不等于无反馈**  
   训练过程中避免红叉、失败音、扣分、责备和羞辱性语言；但局后必须提供温和、可理解的学习反馈，帮助用户知道自己如何进步。

3. **速度与 N 值解耦**  
   加工速度和工作记忆负荷是两个维度。用户可以在慢速下挑战更高 N，也可以在较低 N 下练习稳定性。

4. **同一花园，不同轨道**  
   儿童、成人、老人共享“记忆花园”的世界观，但使用不同任务入口、节奏、文案和反馈强度。

5. **默认简单，进阶可展开**  
   首页默认只展示推荐玩法、推荐素材和推荐节奏。复杂模式、详细数据和高级设置折叠展示。

6. **主舞台纯净**  
   训练刺激出现的主舞台不得播放无关动画。成长、奖励、收藏、成就等反馈放在训练结束或非主舞台区域。

7. **永远可恢复**  
   切后台、锁屏、来电、刷新、返回、音频失败、存储失败、动画关闭等异常场景都必须能安全恢复或回到花园。

8. **无障碍优先**  
   字体、按钮、对比度、触控面积、声音替代、动画减弱、键盘操作、读屏标签都必须作为基础规格，而不是后期补丁。

9. **尊重用户尊严**  
   不暗示用户“记性差”“失败了”“需要被照顾”。所有文案以陪伴、安静、完成感和可持续练习为核心。

10. **本地优先与隐私保护**  
    默认本地记录训练数据。儿童数据、长期趋势和个人设置不得在无明确授权时上传。

## **2. 核心叙事**

### **2.1 世界观**

这是一座安静的记忆花园。

每一次散步，都会遇见花朵、叶子、鸟鸣、微风和小动物。用户要做的不是考试，而是帮花园记住刚刚出现过的事物：哪一朵花回来过，哪一个声音刚刚听过，哪一个花坛位置又亮了起来。

记住了，花园会慢慢生长。  
没记住，也没有关系。花园仍然在那里，下一次散步还会继续。

**花园不是成绩单。花园是练习的地方。**

### **2.2 叙事边界**

原方案中的“健忘症老奶奶”叙事不作为默认主叙事。原因是它可能引发疾病标签、老年刻板印象和用户代入限制。

保留“奶奶的花园”作为可选故事主题，但默认身份统一为：

- 用户是“花园守护者”。
- 花园是“记忆练习场”。
- 每次训练是“一次散步”。
- 每次完成都有“花园生长”。

### **2.3 产品表达声明**

产品中不得使用以下表述：

- 治疗记忆力下降
- 预防认知障碍
- 改善老年痴呆
- 医学级训练
- 临床有效
- 诊断结果
- 失败、差、退步、需努力

推荐使用以下表述：

- 练习注意力
- 练习工作记忆
- 每天一次轻松散步
- 帮花园记住刚刚出现过的花
- 观察最近几次是否更稳定
- 这不是考试，只是一段练习

## **3. 用户轨道设计**

### **3.1 三轨制结构**

| 轨道 | 目标用户 | 核心任务 | 默认体验 |
|---|---|---|---|
| 轻松花园 | 儿童、新用户、老人、低压力用户 | 0-back / 1-back / Go-No-Go | 慢速、单按钮、短局、强引导 |
| 记忆训练 | 成人、熟练老人、长期练习用户 | 标准视觉 N-back | N=1 到 N=3，稳定统计 |
| 花园挑战 | 熟练用户、进阶用户 | 双通道、空间、lure 增强 | 更长局、详细反馈、挑战性更高 |

### **3.2 儿童轨道**

儿童轨道不直接等同成人 N-back。尤其 4 到 6 岁儿童，不应默认进入 N=2 或复杂双通道任务。

儿童轨道按以下阶段递进：

| 阶段 | 名称 | 任务 | 说明 |
|---|---|---|---|
| C0 | 找花花 | 0-back | 看到指定花就按 |
| C1 | 刚刚见过 | 1-back | 当前花和上一朵一样就按 |
| C2 | 小园丁挑战 | 1-back 加少量干扰 | 加入相似但不相同的花 |
| C3 | 亲子挑战 | 2-back 可选 | 需要家长陪同或明确提示 |

儿童轨道默认：

- 总回合数：8 到 12 回合
- 最大 N：默认 1，亲子挑战可到 2
- 单按钮
- 不显示详细数据
- 不使用抽卡式稀有概率作为核心奖励
- 以确定性成长为主，例如“完成 3 次，神秘种子发芽”

### **3.3 成人轨道**

成人轨道是标准训练体验，重点是任务有效性和长期趋势。

成人轨道默认：

- N=1 起步
- 可手动选择 N=1、N=2、N=3
- 可选择单按钮或双按钮
- 可展开查看详细数据
- 自适应仅基于有效训练局，不基于儿童局、练习局或辅助回合

### **3.4 老人轨道**

老人轨道不是“儿童化版本”，而是尊重老年用户的低负荷、高清晰、高容错版本。

老人轨道默认：

- 大字体
- 大按钮
- 慢节奏
- 单按钮
- 强暂停恢复
- 默认关闭复杂动画
- 默认不使用刺耳声音
- 支持完全静音
- 支持“练习不计趋势”模式

## **4. 科学训练内核**

### **4.1 默认任务定义**

默认玩法“散步”采用 Go-No-Go N-back。

用户只在认为“当前刺激与 N 步前刺激匹配”时按按钮；认为不匹配时不操作。

因此单按钮默认玩法不是传统双按钮 N-back，而是：

**Go-No-Go N-back**

系统内部必须区分以下四类结果：

| 内部结果 | 用户行为 | 实际标签 | 含义 |
|---|---|---|---|
| Hit | 按了 | 是目标 | 正确识别 |
| Miss | 没按 | 是目标 | 漏判 |
| False Alarm | 按了 | 非目标 | 误判 |
| Correct Rejection | 没按 | 非目标 | 正确不操作 |

用户界面默认不展示这些术语，但评分、自适应和长期趋势必须基于这些内部指标。

### **4.2 不使用单一准确率作为核心指标**

不得只用 accuracy 判断表现。原因是 Go-No-Go 任务中，如果目标率低，用户全程不按也可能获得较高表面准确率。

内部必须记录：

- 命中率 Hit Rate
- 漏判率 Miss Rate
- 误判率 False Alarm Rate
- 正确拒绝率 Correct Rejection Rate
- 中位反应时 Median Reaction Time
- 反应时稳定性
- 是否出现保守策略
- 是否出现冲动策略
- 是否为有效训练局

### **4.3 推荐内部评分**

MVP 阶段可使用产品化综合分：

```text
Score =
0.45 × HitRate
+ 0.25 × CorrectRejectionRate
- 0.20 × FalseAlarmRate
- 0.10 × MissRate
```

后续进阶版本可加入信号检测指标：

- d-prime，用于衡量辨别敏感性
- response bias，用于衡量用户偏向按或偏向不按

这些专业指标默认不展示给儿童和老人，只用于内部自适应和研究分析。

### **4.4 暖身回合**

每局前 N+1 回合为暖身回合。

暖身回合规则：

- 显示正常刺激
- 用户可按
- 给予温和交互反馈
- 不计入正式评分
- 可计入完成感
- 不用于自适应

原因：N-back 前几回合没有足够历史刺激，直接计分会污染数据。

## **5. Trial Generator 回合生成器**

### **5.1 输入参数**

```typescript
interface TrialGeneratorConfig {
  mode: 'walk' | 'flower-song' | 'flower-bed' | 'garden-grid';
  n: 1 | 2 | 3;
  totalTrials: number;
  warmupTrials: number;
  targetRate: number;
  lureRate: number;
  stimulusSetId: string;
  allowConsecutiveTargets: boolean;
  maxSameStimulusRepeat: number;
}
```

### **5.2 输出 Trial**

```typescript
interface Trial {
  trialIndex: number;
  isWarmup: boolean;
  n: number;
  mode: 'walk' | 'flower-song' | 'flower-bed' | 'garden-grid';

  visualStimulusId?: string;
  audioStimulusId?: string;
  positionId?: string;

  isTarget: boolean;
  targetType: 'none' | 'visual' | 'audio' | 'spatial' | 'conjunctive';

  isLure: boolean;
  lureType?: 'nMinus1' | 'nPlus1' | 'singleChannel' | 'similarStimulus';

  expectedAction: 'press' | 'noPress';
}
```

### **5.3 生成规则**

正式计分回合中：

- 目标率默认 35% 到 40%
- lure 率默认 15% 到 25%
- 连续目标不超过 2 次
- 同一刺激连续出现不超过 2 次
- 同一素材在短时间内不得形成可预测规律
- 暖身回合不计入目标率统计
- 生成失败时最多重试 100 次
- 重试失败则降低 lure 约束，但不得破坏目标率下限

### **5.4 Lure 干扰回合**

lure 是看起来接近目标但不是目标的回合，用于防止用户使用过于简单的策略。

| Lure 类型 | 说明 | 示例 |
|---|---|---|
| nMinus1 | 与 N-1 步前匹配 | N=2 时，当前等于上一朵 |
| nPlus1 | 与 N+1 相关的近邻干扰 | 用于更复杂序列控制 |
| similarStimulus | 与目标相似但不相同 | 两朵颜色相近的花 |
| singleChannel | 双通道中只有一个通道匹配 | 花匹配但声音不匹配 |

MVP 阶段至少实现 nMinus1 和 similarStimulus。双通道模式上线前必须实现 singleChannel lure。

## **6. 记忆素材体系**

### **6.1 素材原则**

正式训练版本不应长期依赖系统 emoji。emoji 可以用于原型，但不同设备上的渲染差异会影响训练一致性。

MVP 建议使用统一风格 SVG 或 PNG 素材。

每个素材需要记录：

```typescript
interface StimulusDef {
  id: string;
  label: string;
  category: 'flower' | 'fruit' | 'animal' | 'word' | 'sound' | 'position';
  visualComplexity: 'low' | 'medium' | 'high';
  similarityGroup?: string;
  colorGroup?: string;
  suitableForChildren: boolean;
  suitableForOlderAdults: boolean;
}
```

### **6.2 视觉素材分级**

| 素材级别 | 用途 | 特征 | 示例 |
|---|---|---|---|
| A 高区分度 | 儿童、老人、新用户 | 轮廓差异大、颜色差异明显 | 向日葵、玫瑰、荷花、叶子 |
| B 中区分度 | 标准训练 | 同类但仍可辨认 | 雏菊、郁金香、木槿、薰衣草 |
| C 高相似度 | 进阶挑战 | 颜色或轮廓接近 | 两种相似花瓣形态 |

### **6.3 MVP 视觉素材集**

MVP 使用 8 到 12 个高区分度花园素材：

```text
rose
sunflower
lotus
tulip
leaf
clover
daisy
strawberry
butterfly
ladybug
apple
mushroom
```

这些素材应统一：

- 画风
- 尺寸
- 明度
- 对比度
- 中心对齐
- 背景透明
- 无多余装饰动画

### **6.4 声音素材原则**

声音模式不进入 MVP。进入 P2 时再实现。

声音素材需要同时满足：

- 舒适
- 可分辨
- 不刺耳
- 不跨回合重叠
- 支持静音替代
- 支持听力适配

声音素材候选：

| 声音 | 有效时长 | 说明 |
|---|---:|---|
| 微风 | 800ms | 柔和、低刺激 |
| 鸟鸣 A | 800ms | 清晰、短促 |
| 鸟鸣 B | 1000ms | 与 A 差异明显 |
| 雨滴 | 1000ms | 节奏清楚 |
| 流水 | 1000ms | 与雨滴需做混淆测试 |
| 虫鸣 | 800ms | 避免高频刺耳 |
| 树叶 | 1000ms | 需避免与微风混淆 |
| 木铃 | 800ms | 可作为非自然但清晰声音 |

声音上线前必须做 8×8 混淆矩阵测试。若用户无法稳定区分，则不得进入双通道训练。

### **6.5 听力适配**

老人模式不默认降低音量，而是提供两种声音配置：

| 配置 | 目标 | 说明 |
|---|---|---|
| 柔和声音 | 避免刺耳 | 降低尖锐峰值 |
| 清晰声音 | 提高辨识 | 保留必要频段，提高边界 |

用户可选择：

- 静音
- 柔和
- 清晰
- 自定义音量

## **7. 模式设计**

### **7.1 模式总览**

| 内部模式 | 花园名称 | 科学任务 | 优先级 |
|---|---|---|---|
| walk | 散步 | 视觉 Go-No-Go N-back | P0 |
| flower-bed | 花坛 | 空间 N-back | P1 |
| flower-song | 花与歌 | 联合匹配双通道 N-back | P2 |
| garden-grid | 花圃 | 视觉阵列记忆 / 进阶 N-back | P3 |

### **7.2 散步模式 P0**

规则文案：

```text
花儿会一朵接一朵出现。
如果这朵花和刚刚见过的那朵一样，就按下按钮。
如果不是，就安静地看它走过。
```

按钮文案：

```text
刚刚见过
```

适用：

- 儿童 C1
- 成人标准训练
- 老人默认训练
- MVP 核心玩法

### **7.3 花坛模式 P1**

规则文案：

```text
花会开在花坛里的一个位置。
如果这次开花的位置和刚刚记住的位置一样，就按下按钮。
```

默认网格：

| 用户轨道 | 默认网格 | 最大网格 |
|---|---|---|
| 儿童 | 2×2 | 3×3 |
| 老人 | 2×3 | 3×3 |
| 成人 | 3×3 | 4×4 |

花坛模式每次只出现一个位置。它是空间 N-back，不是多物体阵列记忆。

### **7.4 花与歌模式 P2**

规则文案：

```text
花园里同时出现一朵花和一个声音。
只有当花和声音都和刚刚记住的一样时，才按下按钮。
```

此模式不是传统 dual N-back 的两个按钮版本，而是：

**联合匹配双通道 Go-No-Go N-back**

必须包含以下回合：

| 回合类型 | 花 | 声音 | 用户应做 |
|---|---|---|---|
| 双匹配目标 | 匹配 | 匹配 | 按 |
| 花匹配 lure | 匹配 | 不匹配 | 不按 |
| 声音匹配 lure | 不匹配 | 匹配 | 不按 |
| 双不匹配 | 不匹配 | 不匹配 | 不按 |

若用户设备静音或音频加载失败，自动禁用此模式或切换到视觉双属性模式。

### **7.5 花圃模式 P3**

花圃模式不进入早期版本。

花圃更接近视觉阵列记忆任务，而不是标准 N-back。它可以作为未来挑战玩法，但不得与核心 N-back 数据混合统计。

## **9. 反馈系统**

### **9.1 反馈原则**

训练中的反馈必须低干扰。局后的反馈必须可理解。

因此采用三层反馈：

| 层级 | 时机 | 目标 |
|---|---|---|
| 即时反馈 | 按钮点击后 | 确认操作，不评价对错 |
| 局后反馈 | 训练结束后 | 温和解释表现 |
| 长期反馈 | 多局之后 | 展示稳定性与适合节奏 |

### **9.2 即时反馈**

按钮被按下时：

- 按钮轻微缩小
- 不播放错误音
- 不显示红色
- 不显示“错了”
- 主舞台不抖动
- 正确时可在迷你花园区出现轻量成长

错误按下不应在主舞台暴露明显错误反馈。避免用户建立“花抖就是我错了”的负面联想。

### **9.3 漏判反馈**

漏判不在训练中即时提示，避免打断任务和制造压力。

局后用花园语言提示：

```text
有几朵花走得很轻，下一次我们可以慢慢看。
```

不得写：

```text
你漏判了 X 次
```

除非用户展开详细数据。

### **9.4 正确反馈**

训练中：

- 迷你花园区轻微生长
- 不遮挡主舞台
- 不播放夸张动画

连续正确时：

- 可出现柔和光感
- 不出现“太棒了”“满分”等强刺激文案
- 儿童模式可适度更活泼，但训练中仍不得遮挡刺激

### **9.5 局后反馈模板**

#### **高稳定表现**

```text
花园今天很安静，也很明亮。

你认出了几朵回来的花，也耐心看着新花走过。
花园多开了一朵小花。
```

#### **中等表现**

```text
今天的花园多了一片新叶。

有些花你认出来了，有些花走得很轻。
每一次散步，花园都会更熟悉你一点。
```

#### **较困难表现**

```text
今天你还是完成了一次散步。

花园里多了一颗种子。
下一次可以走慢一点，只看一朵花就好。
```

### **9.6 详细数据折叠**

成人用户或设置中开启后，可展示：

| 指标 | 用户友好名称 |
|---|---|
| Hit | 认出的回花 |
| Miss | 悄悄走过的回花 |
| False Alarm | 认错的新花 |
| Correct Rejection | 安静看过的新花 |
| Median RT | 平均反应节奏 |

默认儿童和老人不展开详细数据。

## **10. 花朵成长与进度系统**

### **10.1 迷你花园区**

迷你花园区位于顶部，训练中只承担轻量反馈。

规则：

- 高度约 40px 到 56px
- 不展示复杂动画
- 不抢主舞台注意力
- 不影响刺激呈现
- reduced motion 下直接切换状态

### **10.2 成长阶段**

```text
种子 → 破土 → 发芽 → 长叶 → 花苞 → 半开 → 盛开
```

成长触发：

- 正确命中可推动成长
- 完成一局必有最低成长
- 表现更稳定可增加装饰，但不得让低表现用户完全无收获

### **10.3 进度条**

进度条使用“瓢虫走小路”隐喻。

要求：

- 每回合前进一步
- 不在刺激出现时突然跳动
- 不出现复杂翻滚动画
- 儿童模式的趣味动效只在局后或休息页出现

### **10.4 完成奖励**

每局完成都应获得一个确定性成长反馈，例如：

- 一颗种子
- 一片叶子
- 一朵小花
- 一段小路
- 一个花园脚印

表现奖励只作为附加，不作为是否有收获的前提。

## **11. 动效系统**

### **11.1 主舞台动效**

主舞台只允许以下动效：

| 触发 | 动效 | 时长 |
|---|---|---:|
| 刺激出现 | 淡入或轻微浮现 | 200ms 到 300ms |
| 刺激消失 | 淡出 | 200ms 到 300ms |
| 回合间隔 | 空白恢复 | 600ms 到 1000ms |

主舞台禁止：

- 生长动画
- 拟人眨眼
- 随机表情
- 瓢虫翻滚
- 粒子爆炸
- 持续漂浮
- 错误抖动
- 强光闪烁

### **11.2 非主舞台动效**

可用于：

- 迷你花园区
- 结算页
- 收藏册
- 花园日记
- 儿童休息页

但必须支持 `prefers-reduced-motion: reduce`。

### **11.3 儿童拟人化动效边界**

允许：

- 结算页花朵微笑
- 收藏页瓢虫轻微移动
- 神秘种子孵化动画
- 完成后短动画

不允许：

- 训练刺激随机眨眼
- 训练刺激改变表情
- 主舞台出现非任务动画
- 影响用户判断的装饰变化

## **12. 节奏系统**

### **12.1 修正后的统一 Phase 模型**

用户反应窗口与刺激可见期重叠，而不是刺激结束后才开始思考。

每个回合包括：

1. 淡入
2. 可见
3. 淡出
4. 空白恢复

### **12.2 默认节奏表**

| 参数 | 初晨 | 午后 | 暮色 |
|---|---:|---:|---:|
| 淡入 | 300ms | 250ms | 200ms |
| 可见 | 2500ms | 2000ms | 1600ms |
| 淡出 | 300ms | 250ms | 200ms |
| 空白恢复 | 1000ms | 800ms | 600ms |
| 单回合总长 | 4100ms | 3300ms | 2600ms |

### **12.3 局长设置**

| 局型 | 回合数 | 用途 |
|---|---:|---|
| 儿童短局 | 8 到 12 | 熟悉规则、低压力体验 |
| 轻量训练 | 12 到 16 | 日常快速练习 |
| 标准训练 | 24 到 36 | 自适应和趋势统计 |
| 挑战训练 | 36 以上 | 熟练用户挑战 |

短局可以记录，但不建议单独用于强自适应判断。

### **12.4 N 值与速度解耦**

用户可以选择：

- N=1，初晨速度
- N=2，初晨速度
- N=3，初晨速度
- N=1，暮色速度

因此难度不等于速度。  
推荐界面仍可简化为初晨、午后、暮色，但高级设置中必须允许拆分。

## **13. 自适应系统**

### **13.1 自适应原则**

自适应只调整推荐，不强迫用户升级。

用户永远可以选择：

- 留在当前节奏
- 降低节奏
- 暂停自适应
- 只练习不计趋势

### **13.2 有效训练局**

以下局不用于自适应：

- 儿童娱乐局
- 教学局
- 暖身局
- 中途退出局
- 暂停异常局
- 对冲辅助过多的局
- 回合数不足的局
- 音频或素材加载失败的局

### **13.3 推荐自适应逻辑**

```javascript
function adaptiveN(recentSessions, currentN) {
  const valid = recentSessions
    .filter(s => s.validForAdaptation)
    .slice(-5);

  if (valid.length < 3) return currentN;

  const last3 = valid.slice(-3);

  const stableHigh = last3.every(s =>
    s.hitRate >= 0.75 &&
    s.falseAlarmRate <= 0.20 &&
    s.missRate <= 0.25
  );

  const stableLow = last3.every(s =>
    s.hitRate < 0.50 ||
    s.falseAlarmRate > 0.35 ||
    s.missRate > 0.45
  );

  if (stableHigh) return Math.min(currentN + 1, 3);
  if (stableLow) return Math.max(currentN - 1, 1);

  return currentN;
}
```

### **13.4 用户文案**

升 N 推荐：

```text
最近几次散步很稳定。
要不要试试记住更早一点出现的花？
```

降 N 推荐：

```text
今天可以走慢一点。
先从刚刚见过的花开始，也很好。
```

不使用：

```text
你表现不好，已降级。
```

## **14. 反脆弱辅助机制**

### **14.1 目标**

当用户连续困难时，系统提供低压力辅助，避免退赛。

### **14.2 辅助原则**

辅助回合必须：

- 标记为 `wasHedged`
- 不计入能力评估
- 可计入完成体验
- 不影响长期能力趋势
- 不伪装成真实训练成绩

### **14.3 触发条件**

| 条件 | 行为 |
|---|---|
| 连续困难 3 次 | 出现温和提示 |
| 连续困难 4 次 | 下一回合降低干扰 |
| 连续困难 5 次以上 | 推荐暂停或切换初晨 |
| 连续困难 8 次以上 | 自动进入休息建议，不继续加压 |

### **14.4 温和提示**

```text
可以慢一点。
只要看到真的回来过的花，再按就好。
```

### **14.5 不建议强制制造目标回合**

原方案中的“下一回合强制匹配”容易污染数据。  
新方案建议优先使用：

- 降低 lure
- 延长可见时间
- 减少相似素材
- 推荐休息
- 切换练习不计分模式

如果确实生成辅助目标，必须从评分中排除。

### **16.1 核心模块**

  ↓

  ↓

### **16.2 GameEngine 职责**

GameEngine 负责：

- 当前 trial
- 当前 phase
- phaseAge
- 反应窗口
- 暂停恢复
- 输入锁定
- trial 结束
- session 结束
- 事件日志

UI 组件不得直接决定 trial 是否正确。

### **16.3 rAF 状态机**

P0 必须实现 rAF 状态机，不再先用 setTimeout 再迁移。

```javascript
class GameLoop {
  constructor() {
    this.internalAge = 0;
    this.phaseAge = 0;
    this.timeScale = 1;
    this.lastFrameTime = 0;
    this.rafId = null;
    this.phase = 'idle';
  }

  start() {
    this.lastFrameTime = performance.now();
    this.rafId = requestAnimationFrame(this.tick);
  }

  stop() {
    if (this.rafId) cancelAnimationFrame(this.rafId);
    this.rafId = null;
  }

  tick = (now) => {
    const rawDelta = now - this.lastFrameTime;
    this.lastFrameTime = now;

    if (rawDelta > 1000) {
      this.pause('large-frame-gap');
      return;
    }

    const delta = Math.min(rawDelta, 100) * this.timeScale;

    this.internalAge += delta;
    this.phaseAge += delta;

    this.checkPhaseTransition();

    this.rafId = requestAnimationFrame(this.tick);
  };

  pause(reason) {
    this.timeScale = 0;
    this.pauseReason = reason;
  }

  resume() {
    this.lastFrameTime = performance.now();
    this.timeScale = 1;
  }
}
```

### **16.4 后台处理**

当触发以下事件时自动暂停：

- `visibilitychange`
- `pagehide`
- `blur`
- 移动端锁屏
- 来电中断
- 大 delta gap

恢复时不自动继续，显示：

```text
刚刚离开了一会儿。
要继续这次散步吗？
```

按钮：

## **21. 花园收集系统**

### **21.1 设计定位**

花园收集系统是留存与完成感系统，不是训练评分系统。

它必须服务于：

- 完成感
- 温暖反馈
- 长期陪伴
- 可持续回访

它不得制造：

- 成绩羞辱
- 抽卡焦虑
- 儿童诱导
- 强竞争压力

### **21.2 MVP 收集系统**

MVP 不实现 110 个元素。  
MVP 只实现 12 到 20 个轻量花园元素。

初始元素建议：

| 类别 | 元素 |
|---|---|
| 花 | 玫瑰、向日葵、雏菊、郁金香 |
| 叶 | 三叶草、嫩叶、藤蔓 |
| 小动物 | 瓢虫、蝴蝶、蜜蜂 |
| 装饰 | 小石子、木栅栏、小路 |
| 自然 | 晨露、微风、阳光 |

### **21.3 奖励规则**

每局完成必得：

```text
1 个成长点
```

成长点用于：

- 种子发芽
- 花朵开放
- 小路延长
- 花园增加装饰

表现稳定时可额外获得：

- 花瓣颜色
- 微光效果
- 小动物来访

## **25. 测试计划**

### **25.1 科学内核测试**

测试 TrialGenerator：

- 目标率是否稳定
- lure 率是否稳定
- 暖身是否排除
- 连续目标是否超限
- 同刺激重复是否超限
- 生成失败是否可恢复

模拟策略：

| 策略 | 预期 |
|---|---|
| 全不按 | 命中率低，不应得高分 |
| 全按 | 误判率高，不应得高分 |
| 随机按 | 分数不稳定 |
| 理想用户 | 高命中、低误判 |
| 保守用户 | 高正确拒绝但低命中 |

### **25.2 可用性测试**

每类用户至少 3 到 5 人：

- 儿童
- 成人
- 老人

观察：

- 是否理解什么时候按
- 是否理解不按也是选择
- 是否能完成一局
- 是否知道如何再来一局
- 是否感到被评价或被责备
- 是否愿意继续

### **25.3 素材辨识测试**

视觉素材测试：

- 是否一眼可辨
- 是否相似过高
- 是否不同设备显示一致
- 是否对老人足够大

声音素材测试：

- 是否舒服
- 是否清楚
- 是否互相混淆
- 是否适合小扬声器

### **25.4 节奏测试**

至少测试三种节奏：

- 4100ms
- 3300ms
- 2600ms

记录：

- 完成率
- 主观疲劳
- 平均反应时
- 漏判率
- 误判率
- 是否走神

### **25.5 工程异常测试**

必须测试：

- 切后台
- 锁屏
- 来电
- 返回
- 刷新
- 横竖屏
- 慢设备
- 动画关闭
- 音频失败
- 素材失败
- localStorage 满
- 连续点击
- 键盘操作

interface PersistedData {

### **28.2 迁移原则**

- 永远优先保留用户设置
- 其次保留花园成长
- 再保留 session 摘要
- 最后保留 trial 明细
- 迁移失败时不得白屏
- 提供重置入口

### **28.3 旧成就迁移**

旧成就迁移为基础花园元素：

```javascript
function migrateAchievementsToGarden(oldAchievements) {
  const garden = {};

  const map = {
    'first-flower': 'seed',
    'green-thumb': 'sprout',
    'memory-master': 'sunflower',
    'perfect-score': 'morning-dew',
    'n2-legend': 'stone-path',
    'n3-master': 'garden-gate',
    'streak-5': 'breeze',
    'persistent-gardener': 'sapling',
    'multi-factor': 'butterfly'
  };

  Object.entries(oldAchievements).forEach(([oldId, unlocked]) => {
    if (unlocked && map[oldId]) {
      garden[map[oldId]] = {
        id: map[oldId],
        count: 1,
        discovered: true,
        firstFoundAt: new Date().toISOString(),
        lastFoundAt: new Date().toISOString()
      };
    }
  });

  return garden;
}
```

## **29. 附录 D：MVP 验收标准**

MVP 可以上线内测的标准：

1. 用户能在 30 秒内理解散步模式。
2. 用户能完整完成一局。
3. 系统能正确记录 Hit、Miss、False Alarm、Correct Rejection。
4. 全不按策略不会得到高训练评分。
5. 切后台后不会继续消耗回合。
6. reduced motion 下仍可玩。
7. 老人模式下按钮和文字足够大。
8. 儿童模式不会进入过难 N-back。
9. 结算文案没有羞辱或医疗暗示。
10. 本地数据可清除。
11. TrialGenerator 通过模拟测试。
12. 错误边界不会白屏，能回到花园。

## **30. 当前版本决策**

v5.0 的核心决策如下：

1. MVP 只做“散步”视觉 Go-No-Go N-back。
2. 默认使用单按钮，但内部按 Go-No-Go N-back 评分。
3. 不再用 accuracy 作为唯一核心指标。
4. 引入 Hit、Miss、False Alarm、Correct Rejection 和 RT。
5. 引入 trial generator 与 lure 控制。
6. 儿童、成人、老人分轨。
7. 训练中低干扰，局后温和学习反馈。
8. 110 元素收集、声音模式、3D 花园全部后移。
9. rAF 状态机进入 P0。
10. 产品明确不是医疗工具。
